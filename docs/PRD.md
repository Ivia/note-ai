## 1. 产品背景与定位

### 1.1 背景
小红书创作者有三个高频痛点：
- **新手起号不知从何开始**：不会选赛道、不会对标、不会定位；
- **老玩家撞到瓶颈**：不清楚自己内容问题在哪；
- **单篇创作耗时长**：标题、正文、标签、配图思路样样要琢磨。

市面上通用 AI 工具（ChatGPT、Claude 原生）对小白门槛太高：要科学上网、要写提示词、要会组合工具。

### 1.2 产品定位
**面向小白的小红书爆款笔记 AI 生成器。** 用户只做"选"和"填"，工具替他完成所有专业创作步骤。

一句话：**把小红书创作专家的工作流，封装成 3 个按钮。**

### 1.3 产品原则
1. **傻瓜式**：用户不配置、不写提示词、不折腾。
2. **零感知后端**：用户侧体验是"打开网页就能用"，背后 Serverless 运维近零。
3. **场景驱动**：只做三个典型场景，不做通用 Chat。
4. **合规优先**：明确免责、尊重原创、不鼓励洗稿。

## 4. 功能需求

### 4.1 功能总览

```
┌───────────────────────────────────────────────────┐
│  小本本 · 小红书 AI 创作助手                         │
├───────────────────────────────────────────────────┤
│  [场景 1] 新手起号助手   — 赛道对标 + 起号规划       │
│  [场景 2] 账号诊断优化   — 历史内容分析 + 风格调优   │
│  [场景 3] 单篇文案生成   — 主题+风格 → 爆款笔记       │
├───────────────────────────────────────────────────┤
│  [通用] 账号与订阅 / 历史记录 / 导出 / 免责声明       │
└───────────────────────────────────────────────────┘
```

### 4.2 场景一：新手起号助手

**用户流程**
1. 选择"新手起号"
2. 填写垂类方向（预设 10 个常见赛道 + 自由输入）
3. 填写个人定位标签（年龄段、身份、资源等多选 + 自由输入）
4. 选择起号目标（涨粉 / 带货 / 个人品牌）
5. 提供对标数据源（三选一，按用户操作难度排序）：
   - **方式 A（推荐）**：输入赛道关键词，工具自动搜索小红书热门笔记（**依赖 Serverless 代理**）
   - **方式 B**：粘贴 3–5 个对标博主主页链接
   - **方式 C**：跳过（仅凭模型知识，质量打折）
6. 一键生成

**输出物**
- **对标分析报告**：共性选题、标题套路、封面风格、互动话术
- **账号定位建议**：切入点、差异化、昵称/简介范例
- **前 5 篇起号笔记**：每篇含标题 3 选 1 + 正文 + 话题 + 配图思路
- **30 天内容节奏表**：每周主题 + 发帖频率

**需求优先级**

| 功能点 | 优先级 |
| --- | --- |
| 方向 + 定位输入 | P0 |
| 小红书搜索（方式 A） | P0 |
| 对标分析 + 起号笔记 + 节奏表 | P0 |
| 链接对标（方式 B 兜底） | P1 |

### 4.3 场景二：账号诊断优化

**用户流程**
1. 粘贴自己的小红书主页链接
2. 选择诊断时间范围（近 1 / 3 / 6 个月）
3. 工具通过 Serverless 代理拉取主页近 N 篇笔记（含阅读/点赞/评论数据）
4. 一键生成

**输出物**
- **账号画像**：当前赛道、风格标签、爆款比例
- **内容诊断**：哪类选题表现好/差、标题/封面问题
- **优化建议**：赛道聚焦/扩展、可复用的爆款结构
- **下一步选题池**：10 个贴合自身风格的新选题

**需求优先级**

| 功能点 | 优先级 |
| --- | --- |
| 主页链接自动拉取 | P0 |
| 诊断报告 + 选题池 | P0 |
| 批量手动粘贴（拉取失败的兜底） | P1 |

### 4.4 场景三：单篇文案生成

**用户流程**
1. 填写笔记主题（如"推荐 3 款平价 CC 霜"）
2. 填写核心卖点 / 想表达的信息
3. 选择风格（预设 6 种：干货科普 / 情绪共鸣 / 踩坑避雷 / 沉浸 VLOG / 清单测评 / 自由）
4. 可选：粘贴 1 篇参考笔记链接作为风格对标（走 Serverless 代理）
5. 一键生成

**输出物**
- **3 组标题候选**（正标题 + 副钩子）
- **正文**（含 emoji、分段、结尾互动）
- **话题标签**（5–8 个）
- **配图思路**（6–9 张，每张含"画面内容 + 文字贴纸"）
- 任一部分可单独"重新生成"

**需求优先级**：P0，**此场景是 MVP 主打**。

### 4.5 通用功能

#### 4.5.1 账号与订阅（付费闭源模式）
- 用户注册 / 登录（邮箱 + 验证码 或 微信扫码）
- 订阅状态展示（免费试用额度 / 付费期至）
- 订单管理
- 建议：首次注册送 **3 次免费生成**，作为试用钩子

#### 4.5.2 模型（MVP 仅 Claude）
- MVP 阶段工具后端固定调用 **Claude** （Anthropic API），用户无需配置 Key
- API 成本由产品方承担，计入订阅价定价
- V2 再考虑多模型可选

#### 4.5.3 历史记录
- 所有生成结果存本地 IndexedDB + 云端同步（与账号绑定）
- 支持：查看 / 复制 / 删除 / 导出 Markdown

#### 4.5.4 导出
- 单篇：一键复制 / 导出 .md
- 报告类：导出 PDF（P1）

## 5. 技术方案

### 5.1 架构

```
┌────────────────┐         ┌──────────────────────┐
│  浏览器（用户）  │ ──────> │ Cloudflare Workers    │
│  纯静态 Web     │ HTTPS   │ (Serverless)          │
│  (Next.js)      │         │  - 小红书爬取代理      │
│                 │         │  - Claude API 代理     │
└────────────────┘         │  - 鉴权 + 计费         │
                            └──────────────────────┘
                                      │
                        ┌─────────────┼─────────────┐
                        ▼                           ▼
                 小红书公开页面                Claude API
                 (m.xiaohongshu.com)         (Anthropic)
```

### 5.2 技术栈

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | Next.js + React + TailwindCSS | 部署到 Cloudflare Pages（免费） |
| 后端 | Cloudflare Workers | 每天 10 万次请求免费 |
| 数据库 | Cloudflare D1（SQLite） | 免费额度 5GB |
| 鉴权 | Clerk / 自建 JWT | 用户体系 |
| 支付 | 微信支付 / 支付宝（付费用户侧主力） | |
| 模型 | Claude（claude-sonnet-4-6） | 通过官方 API |

**关键点**：整套架构在用户量 < 5000 日活时，Cloudflare 完全免费。

### 5.3 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 前端交互 < 500 ms；模型响应流式输出，首字 < 3s |
| 兼容 | Chrome / Edge / Safari 最新两版，桌面优先 |
| 安全 | 用户生成内容仅与账号绑定，API Key 仅服务端持有 |
| 可用性 | MVP 阶段不追求 SLA，提供"稍后重试"兜底 |

### 5.4 小红书内容获取（关键实现）

**方案**：Cloudflare Workers 作为代理，访问小红书 Web 端（m.xiaohongshu.com）解析 HTML/JSON。

**潜在风险与应对**：
- **反爬**：小红书有频率限制、Referer 校验、部分数据需登录。
  - 应对：使用 Worker 的多 IP 出口 + 合理频控；必要时接入低成本第三方数据服务（如新榜 API）兜底。
- **页面结构变动**：小红书改版可能导致解析失败。
  - 应对：抓取逻辑与业务逻辑解耦，Workers 上热更新即可修复，不影响前端。
- **合规**：见 §7 免责声明。

> 5. AI 生成内容可能包含不准确信息，**涉及健康、医疗、法律、金融等专业领域时请以专业意见为准**。
